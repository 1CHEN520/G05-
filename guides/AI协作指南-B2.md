## 一、用哪种 AI

| 优先级 | 工具形态 | 具体建议 | 为什么适合你 |
|---|---|---|---|
| **主力** | 能读文件 + 能跑命令的 Agent 型（Claude Code / Cursor Agent） | 任选 | BFS 的边界条件（环、深度上限、截断）必须靠跑用例验证，光看代码看不出来 |
| **主力补充** | 推理型模型（Claude / o 系列 / DeepSeek-R1 类） | 想算法时用 | 环检测、路径回溯这类逻辑，推理型模型的正确率明显高一档 |
| **备选** | 网页对话 | 讨论 SVG 布局思路 | 布局是几何问题，画个草图比读代码快 |
| **不推荐** | 纯补全插件 | — | 补全出来的 BFS 十有八九没有 visited 集合 |

**一条硬要求**：让它写 BFS 时，**必须要求"给出 visited 集合的维护位置和更新时机"**。不主动问，它经常把 `visited.add()` 写在 `pop` 之后，导致同一节点入队多次。

## 六、你这个角色专属的技巧

### 1. 让 AI 画"入队顺序表"，别只看代码

BFS 最容易错的是 visited 的时机。让它输出执行轨迹：

```
对这张图（A→B, A→C, B→D, C→D），请给出 BFS 每一步的：
队列内容 / 当前节点 / visited 集合 / 已记录的 path
用表格输出，不要写代码。
```

表格一对，错在哪一步立刻看得见。

### 2. 环检测要让 AI 说清"用哪套机制"

项目里有**三道**防环，别混：

| 机制 | 位置 | 拦住什么 |
|---|---|---|
| BFS 的 `visited` | 应用层 | 查询时不死循环 |
| 路径回溯比对 | 应用层 | 识别并**报告**环（返回 `cycles` 字段） |
| 触发器 `trg_edge_no_self_loop` | 数据库 | 自环边直接拒绝写入 |

问它："这三道分别在什么场景生效？哪一道是我要写的？" 答不清就说明它把概念混了。

### 3. 截断必须"诚实"

```
请检查我的截断逻辑：截断时除了 truncated=true，还必须告诉调用方什么？
（提示：总数、已返回数、被截掉的是哪些类型）
```

截断后如果只返回 `truncated: true` 而不给"总共有多少"，前端就没法提示"还有 N 个未显示"，用户会以为这就是全部——这是"数据说谎"，比报错更糟。

### 4. 布局用 AI 算坐标，别让它画 SVG

```
给定 200 个节点、3 个圈层（外圈测点 120 个 / 中圈数据集 50 个 / 内圈消费方 30 个），
画布 900x600，中心 (450,300)。请给出：
1. 每圈的半径（要保证相邻圈之间留 40px 标签空间）
2. 每个节点的 (x, y) 计算公式
3. 标签的旋转角度规则（避免重叠）
只给公式和参数，不要写 SVG。
```

坐标公式对了，SVG 只是套模板；反过来会陷在 `transform` 里出不来。

## 八、常见翻车与应对

| 现象 | 原因 | 应对 |
|---|---|---|
| 查询卡死不返回 | 图里有环，visited 没生效 | 先跑"二元环"用例；检查 visited 加入时机 |
| 影响面数量偏多 | 同一节点被多条路径重复计数 | visited 在入队时加，不是出队时 |
| 影响面数量偏少 | 只查了一层就返回 | 检查 while 循环的终止条件 |
| 200 节点渲染卡顿 | 每个节点都创建了事件监听 | 用事件委托，在 SVG 根上监听 |
| 标签重叠 | 半径不够或没做错位 | 加半径 / 隔一个节点隐藏标签 / 悬停显示 |
| SQL 条数随节点数涨 | N+1 | 改成按层批量 `IN` 查询 |
| 别人打开血缘页白屏 | 你的 `lineage.js` 报错影响了全局 | 单独包一层 `try/catch`，并在 `main.js` 里做容错调用 |

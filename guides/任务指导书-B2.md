## 五、技术要点

### 1. BFS 的三个必须项

```python
visited: set[int] = {root.id}          # ① 必须，否则环会死循环
depth: dict[int, int] = {root.id: 0}   # ② 层数要能被前端用
path: dict[int, list[str]] = {}        # ③ 每条路径要能还原，不能只给"深度"
```

只给"影响 11 个对象"是不够的，老师会问"凭什么说这 11 个"——要给**路径**：`FAN0001_VIB → DS_CLEAN_TS → RPT_OEE_DAILY`。

### 2. 方向别搞反

- `downstream`：从根出发，沿 `upstream_id → downstream_id` 走（我影响谁）
- `upstream`：反向走（谁影响我）

两个方向共用一套 BFS，只是"邻居"的取法不同。**别写两份代码**。

### 3. 批量取邻居，别在循环里查库

```python
# ❌ 慢：每个节点一次查询
for nid in frontier:
    neighbors = session.query(LineageEdge).filter_by(upstream_id=nid).all()

# ✅ 快：一层一次查询
rows = session.execute(
    select(LineageEdge).where(LineageEdge.upstream_id.in_(frontier))
).scalars().all()
```

200 个节点的图，前者几百次 SQL，后者 3 次。这就是"<1s"和">5s"的区别。

### 4. 截断要诚实

节点数超过 `max_nodes`（`config/app.yaml` 里配）时，返回 `truncated: true`，前端显示"结果已截断"。
**不要**悄悄截断——用户会以为影响面就这么大。

### 5. 前端：标签策略决定可读性

193 个节点全标标签 = 一团糊。规则：

- `nodes.length <= 45`：全标
- 否则：只标**非测点节点**（hub）+ 根节点
- 标签沿径向向外偏移，避免同圈互相压住

### 6. 零依赖红线

前端**不许**引入 d3/cytoscape/echarts（离线答辩，CDN 拉不到就白屏）。用 `document.createElementNS` 手写 SVG。这段代码不短，但可控、可离线。

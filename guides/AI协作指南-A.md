# AI 协作指南 · A（陈锦妍）

> 读者：你自己。**《任务指导书-A》是给 AI 读的，这份是给你读的。**
> 你的三重身份：组长（要分活）／架构师（要定契约）／唯一有仓库权限的人（要合 PR）。
> 所以你的 AI 用法和别人不一样：**你不是让它写功能，是让它帮你守住一致性。**

---

## 一、用哪种 AI

| 优先级 | 工具形态 | 具体建议 | 为什么适合你 |
|---|---|---|---|
| **主力** | 能读写本地文件 + 能跑命令的 Agent 型（Claude Code / Cursor Agent / Codebuddy 等 IDE Agent） | 任选一个你顺手的 | 你要做的是"跨 20 个文件的一致性检查"，只有能自己 `grep`、自己跑 `pytest` 的工具才做得动 |
| **主力补充** | 同一个 Agent 的"大上下文"模式 | 开新会话时贴 `docs/02-架构设计.md` | 契约评审要看全文，上下文不够会漏掉冲突 |
| **备选** | 网页对话（DeepSeek / Kimi / 通义千问） | 用来写文档初稿、想措辞 | 免费、中文好；但**不能替你验证**，代码类回答必须自己跑一遍 |
| **不推荐** | 纯 Tab 补全插件 | — | 它只看见光标附近 200 行，看不见"C4 的接口和 B1 的模型对不对得上" |

**一条硬要求**：不管用哪个，**必须能让你在同一个会话里看到它跑命令的输出**。你要审的是"证据"，不是"承诺"。

## 三、环境配置（你已经配好了，这一步是给"换机器"和"帮别人排查"用的）

### 3.1 你自己的环境自检（1 分钟）

打开 **Anaconda Prompt**（不是普通 PowerShell），执行：

```bat
conda activate pp03
python -c "import sys; print(sys.version); print(sys.executable)"
cd /d D:\G05
python -c "import g05; print(g05.__file__)"
python -m g05 preflight
```

**判断标准**：

| 输出 | 含义 |
|---|---|
| `sys.executable` 含 `envs\pp03` | 环境对了 |
| `g05.__file__` 是 `D:\G05\src\g05\__init__.py` | editable 指向本仓库，对了 |
| `preflight` 的 `"passed": true` | 骨架健康 |

任一条不对 → 跳到 `docs/04-环境搭建步骤.md` 的「六个必踩的坑」，先修环境再干活。

### 3.2 帮组员排查时用的提示词

组员报"装不上"时，把下面这段和**他的完整报错**一起发给 AI：

```
我的组员在配 G05 环境时报错如下（贴完整报错，不要摘要）：

<粘贴>

背景：
- 项目：Python 3.12 + SQLAlchemy 2.0 + FastAPI，四层环境
- 第 1 层 conda 只装 python=3.12 和 pip，第 2/3/4 层全用 pip
- 已知坑：conda-launchers 元数据损坏、editable 指向别的目录、conda activate 静默失败

请按这个顺序回答，不要跳步：
1. 这个报错属于"环境层"还是"项目层"？
2. 最可能的 3 个原因，按概率排序，每个给一条验证命令
3. 修复命令（要能直接复制，Windows + Anaconda Prompt）
4. 修好后用什么命令确认真的好了
```

**为什么这么问**：`docs/04` 已经收录了 7 个坑，AI 的答案如果和文档冲突，**以文档为准**（文档是本机实测的）。

### 3.3 你要额外做的一步：把环境基线钉死

你是唯一有权限改 `requirements.txt` 的人。任何人说"装个新包"，你的判断顺序：

1. 标准库能不能做？（能就不装）
2. 项目里已有的包能不能做？（能就不装）
3. 必须装 → 钉死版本号写进 `requirements.txt` → 跑 `pip check` → 更新 `docs/04` 的包清单

**别让 AI 随手 `pip install`**。它装的版本不进 `requirements.txt`，别人的机器上就跑不起来——这是"在我机器上能跑"的头号来源。

## 四、项目初始化提示词（第一次对话，整段复制）

```
你是我的架构与协作 AI。我是 G05 项目的组长兼架构师，真名陈锦妍。

## 项目背景
- 工业级 L2 项目：设备台账与测点资产目录，带血缘追踪与不可篡改审计
- 技术栈：Python 3.12 / SQLAlchemy 2.0（Mapped 风格）/ FastAPI / SQLite(WAL) / 原生 HTML+CSS+JS（零前端依赖）
- 团队 9 人：A（我，架构+骨架）、B1（建模+ORM）、B2（血缘引擎）、C1（导入器）、C2（校验规则）、C3（审计）、C4（CRUD+控制台）、C5（测试+压测）、C6（文档+运维）
- 仓库根目录：D:\G05

## 第一步：读文件，只输出清单，不要写代码
按顺序读，读完给我一份"已读清单"（文件名 + 一句话说它管什么）：
1. guides/任务指导书-A.md        ← 我的岗位说明书，最重要
2. collab/roles.yaml             ← 文件归属的唯一事实来源
3. collab/issues.yaml            ← 39 个 issue 的依赖与验收
4. docs/02-架构设计.md
5. src/g05/schemas/dto.py
6. src/g05/main.py
7. src/g05/core/config.py

## 第二步：回答三个问题（找不到就说"文件里没有"，不许猜）
1. 全项目 98 个文件按 9 个角色怎么分的？哪几个文件是"多人可能要改"的冲突点？
2. M1 里程碑里，哪些 issue 是阻塞别人的关键路径？按顺序列出来。
3. 如果 B1 的模型和 C4 的接口对不上，现在的机制能不能提前发现？缺什么？

## 第三步：给我一个"骨架推送检查单"
我要先把骨架推到远端，其余文件由组员各自推。请列出：
- 哪些文件属于骨架（我推）
- 哪些文件必须留空/占位（别人推）
- 推之前必须验证哪几件事

## 工作约定（每次对话都适用）
1. 改任何文件前，先说：改哪个文件、改什么、为什么、影响谁
2. 不许改 collab/roles.yaml 之外我没授权的归属
3. 不许编造命令输出。没跑过就说"未验证"
4. 我的代码风格：类型注解齐全、中文注释、行宽 110
5. 中文回答
```

### 它应该怎么回答（用来判断有没有真读懂）

| 检查点 | 合格回答长什么样 |
|---|---|
| 已读清单 | 7 个文件都列了，且 `roles.yaml` 说的是"归属事实来源"而不是"配置文件" |
| 冲突点 | 至少点出 `schemas/dto.py`、`core/**`、`main.py`、`config/*.yaml` 这四类 |
| 关键路径 | 能说出 `G05-01 → G05-02/03 → G05-06/08 → G05-10 → 其余` 这条链 |

## 五、日常四类提示词

### 5.1 契约变更评审（你最常用的）

```
有人提了要改 schemas/dto.py：<贴 issue 链接或改动内容>

请按这四点评估，每条给结论 + 理由：
1. 破坏性：现有调用方（C1/C2/C4/B2）谁会因此报错？列出具体文件与行号
2. 兼容方案：能不能加字段而不是改字段？能不能给默认值？
3. 迁移成本：如果必须改，谁要跟着改、改几处？
4. 验收：改完用什么命令证明没弄坏别处？
最后给我一句话结论：批准 / 有条件批准 / 驳回。
```

### 5.2 跨模块一致性检查（每周做一次）

```
做一次全项目一致性体检，只读不改，输出表格：
1. DTO 字段 vs 模型字段：有没有对不上的（缺字段、类型不一致、可空性不一致）
2. config/*.yaml 里的键 vs 代码里 settings.get() 的键：有没有取了不存在的键
3. 路由前缀 vs 前端 fetch 的路径：有没有 404 风险
4. 每个模块的 __init__.py 导出 vs 实际被 import 的名字
5. 审计覆盖：_AUDITED_TABLES 里的表 vs 实际有写操作的表

每项给出：文件:行号 + 问题 + 严重度（阻断/警告/提示）。
没有问题就写"无"，不要凑数。
```

### 5.3 PR 评审（每个 PR 都要跑）

```
请评审这个 PR（我把 diff 贴在下面 / 你可以直接看 feat/xxx 分支）：

按六点检查，每点给"通过/不通过 + 依据（文件:行号）"：
1. 是否只改了他名下的文件？有没有偷偷改契约？
2. 有没有配测试？测试断言的是行为还是实现？
3. 有没有魔法数字？该进 config 的进了吗？
4. 异常路径有没有处理？错误码符合 G05-1xxx/2xxx/5xxx 吗？
5. 有没有破坏"零前端依赖""软删不物理删""审计只追加"这三条铁律？
6. 提交信息是否符合 type(scope): 描述？

最后给结论：可以合 / 改完再合（列出必须改的几条）。
```

### 5.4 卡住时的"降维"提问

```
我在 <具体位置> 卡住了，现象是 <贴报错/贴现象>。
我已经试过：<列出试过的>。
请你：
1. 先用一句话说出你认为的根本原因（如果信息不够，直接说"信息不足，需要 X"）
2. 给我一个"最小复现"：3 行以内能验证你判断的命令
3. 只有第 2 步验证通过后，才给修复方案
```

**为什么强调"最小复现"**：AI 最爱直接给一大段修复代码。你先让它证明判断对，能省掉 80% 的无效改动。

## 六、你这个角色专属的技巧

### 1. 让 AI 读 `roles.yaml`，不要让它读你的口头描述

归属关系有 98 个文件、9 个角色，口头描述必错。正确姿势：

```
文件归属以 collab/roles.yaml 为准。请先读它，再回答"src/g05/core/schema.py 归谁"。
```

### 2. 用 AI 生成"检查脚本"，而不是让它手工检查

一致性检查每次都要做，让 AI 写成脚本（`scripts/` 下，你名下）比每次对话便宜：

```
把刚才那五项体检写成 scripts/check_consistency.py，要求：
- 只用标准库 + 项目已有依赖
- 输出 Markdown 表格，能直接贴进 PR
- 有问题返回非 0 退出码，能接进 CI
```

### 3. 契约冻结后，让 AI 当"守门人"

冻结 `dto.py` 之后，每次 PR 都问一句：

```
对比 main 分支和这个 PR 的 src/g05/schemas/dto.py，列出所有字段级变化（新增/删除/改名/类型变化/可空性变化）。
如果为空，回答"无契约变更"。
```

这一句能挡住 90% 的"顺手改了个字段名"。

### 4. 分发包出问题，先查归属再查脚本

```bat
python scripts/make_role_bundles.py --check
```
它会告诉你哪些文件没归属、哪些被两个人同时认领。**归属冲突是分发包失败的第一原因**，不是脚本 bug。

## 七、红线（对 AI 说什么都不行）

| 不许 | 为什么 |
|---|---|
| 让它"顺手把别人的文件也改了" | 你的 PR 会变成巨型 diff，评审失效，追溯断裂 |
| 让它改 `collab/issues.yaml` 的验收标准来"让它通过" | 验收标准是给老师看的，不是给 CI 看的 |
| 让它生成"看起来对"的测试通过截图 | 学术诚信 |
| 让它在 `main` 上直接提交 | 分支保护就是为你设的 |
| 接受它"应该可以""理论上没问题"的结论 | 你是最后一道关，必须看到命令输出 |
| 把 `requirements.txt` 的版本改成 `>=` 范围 | 换机器必炸，全部钉死 `==` |

## 八、常见翻车与应对

| 现象 | 原因 | 应对 |
|---|---|---|
| 组员说"我 clone 下来跑不起来" | 骨架里缺他需要的文件，或 `preflight` 的 soft 检查被当成失败 | 让他贴 `preflight` 的完整 JSON；`soft_failures` 不算失败 |
| 两个人 PR 改同一个文件 | 归属表有漏洞，或有人跨边界没走 issue | `make_role_bundles.py --check` 找冲突，补进 `roles.yaml` |
| CI 一直红但本地绿 | Python 版本/依赖版本不一致 | 对齐 3.12 + 钉死版本，让 C5 查 |
| 演示前发现某个功能是空的 | 该 issue 没进 M3，被 M4 的文档活挤掉了 | 每周看一次 `collab/issues.md` 的里程碑分布 |
| AI 给的方案越改越乱 | 上下文里混了太多历史尝试 | 开新会话，只贴"当前状态 + 目标 + 约束"三样 |

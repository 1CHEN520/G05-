## 两份文件分别怎么用

**《任务指导书》** —— 给 AI 读的"岗位说明书"。
里面有：你负责哪些文件、要完成哪些 issue、技术要点、易错点、验收命令。
用法：开工第一步，把这份文件**整篇**丢给 AI，让它先读完再动手。

**《AI 协作指南》** —— 给你自己读的"操作手册"。
里面有：用哪种 AI、开工前准备什么、初始化提示词（直接复制粘贴）、环境配置提示词、日常四类提示词、红线。
用法：第一次照着做一遍，之后只查"提示词"那一节。

## 怎么发到每个人手上

**每人一个 zip，一个 zip 就是他要的全部东西**：说明 + 提交信息 + 两份指导书 + 他负责的代码。

```bash
# 组长执行一次，产出 dist/roles/<CODE>/ 九个目录 + dist/zips/G05-<CODE>.zip 九个压缩包
# （dist/ 已被 .gitignore 排除，不会进远端）
python scripts/make_role_bundles.py --zip
```

包内结构：

```
G05-C3.zip
└── C3/
    ├── _bundle/
    │   ├── README.md              ← 推送步骤，照它做
    │   ├── COMMIT_MSG.txt         ← 提交信息，直接 git commit -F 引用
    │   ├── 任务指导书-C3.md        ← 丢给组员的 AI 读
    │   └── AI协作指南-C3.md        ← 组员本人读
    └── files/                     ← 他负责的文件，按原相对路径排好
```

**发的时候说清三句话**：

1. 先按《AI 协作指南》第二节把 `pp03` 环境配好，再动代码。
2. 《任务指导书》整篇丢给你的 AI，让它读完再开始。
3. 只推 `files/` 里的文件到你自己的分支，步骤见 `_bundle/README.md`。

谁拿哪个包、包里有什么、发放勾选表，见 [`collab/分发包发放清单.md`](../collab/分发包发放清单.md)。

## 所有人的共同底线

1. **只改自己名下的文件**。归属见 [`collab/分工文件清单.md`](../collab/分工文件清单.md)。
   确实要动别人的文件（`schemas/dto.py`、`config/*.yaml`、`models/base.py`、`core/**`、`main.py`）→
   **issue 里说清 → 在自己分支改 → PR 里由 CODEOWNERS 要求原负责人一起 approve**。
   这是全项目唯一允许的"跨边界"方式，不许跳过评审直接合。
2. **配置外置**。可调参数写进 `config/*.yaml`，代码里不出现魔法数字。
3. **每个功能配一条测试**。`python -m pytest -q` 必须全绿才算完成。
4. **提交前自检**。`python -m g05 preflight` 的 `passed` 必须是 `true`。
5. **不编造结果**。没跑过的命令，不许写"已验证"。

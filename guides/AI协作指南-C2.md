# AI 协作指南 · C2（李梓旭）

> 读者：你自己。**《任务指导书-C2》是给 AI 读的，这份是给你读的。**
> 你的核心矛盾，一句话：**评分用来衡量质量，但不能让脏数据靠高分蒙过门禁。**
> 所以你的 AI 用法核心是：**先让它说清"致命 vs 普通"，再让它写规则。**

---

## 一、用哪种 AI

| 优先级 | 工具形态 | 具体建议 | 为什么适合你 |
|---|---|---|---|
| **主力** | 能读文件 + 能跑命令的 Agent 型（Cursor Agent / Claude Code） | 任选 | 你要反复改 YAML 看行为变化，必须让它自己跑、自己贴输出 |
| **主力补充** | 同一个 Agent，让它先输出"规则-用例对照表" | 每个规则类都做 | 八类规则 × 正例/反例 = 16 条以上，靠脑子记必漏 |
| **备选** | 网页对话（DeepSeek / Kimi） | 查 YAML 语法、想评分公式 | 但它看不到 `rules.yaml` 的真实结构，容易给你编一个不存在的键 |
| **不推荐** | 纯 Tab 补全 | — | 补全出来的 `if` 判断往往把"致命"和"普通"混在一起 |

**一条硬要求**：每次让它动校验逻辑，先问一句"**这条规则是致命的还是普通的？为什么？**" 它答不上来，就不要让它写。

## 四、项目初始化提示词（第一次对话，整段复制）

```
你是我的结对开发 AI。我是 G05 项目的 C2（校验规则引擎），真名李梓旭。

## 硬性技术约束
- 规则全部外置在 config/rules.yaml，代码里不许出现写死的阈值、枚举、列名
- 八类规则：required / type / enum / range / unique / foreign_key / regex / length
- 致命规则（一票否决）：required / unique / foreign_key。其余是普通规则
- 评分只衡量质量，不能覆盖致命错误：fatal_count > 0 时 passed 必须为 false
- foreign_key 规则必须查数据库，不能只查同批数据
- 问题必须定位到 Excel 真实行号（表头是第 1 行）
- 代码风格：类型注解齐全、中文注释、行宽 110

## 第一步：读文件，只输出清单，不要写代码
1. guides/任务指导书-C2.md              ← 我的岗位说明书，最重要

4. src/g05/importers/bulk_importer.py   ← C1 怎么用我的 report.passed
5. tests/test_validator.py
6. src/g05/reports/                     ← 报告导出（我要新建）

## 第二步：回答五个问题（找不到就说"文件里没有"，不许猜）

2. FATAL_RULES 包含哪几类？为什么这三类特殊，而不是 enum/range 也致命？
3. 评分三段（完整性/合规性/唯一性）各自的分子分母是什么？

表格形式，不要写代码。

## 工作约定

3. 不许编造命令输出，没跑过就说"未验证"
```

### 它应该怎么回答（判断有没有读懂）

| 检查点 | 合格回答 |
|---|---|
| passed 算法 | 说得出 `passed = score >= threshold and fatal_count == 0`，**且能举出"87 分被打回"的例子** |
| 致命三类 | 说得出"缺必填 → 下游拿不到信息；重复 → 覆盖；外键悬空 → 孤儿"，是结构不成立而非质量差 |

## 五、日常四类提示词

### 5.1 加一条规则

```
我要加一条 <规则类型> 规则，作用在 <sheet>.<列>。
请按顺序输出：
1. YAML 片段（带注释，业务方要能看懂）
2. 代码改动点（在 validator.py 的哪个位置，改什么）
3. 两条用例：正例 + 反例
4. 这条规则是致命还是普通？为什么？
5. 会不会让现有样例数据从"通过"变"不通过"？如果有，是哪几行？

先给 1、4，我确认后再写代码。
```

**第 5 条最容易被忽略**：加严规则会让历史数据突然导不进来，这是真实的业务影响。

### 5.2 排错（"为什么这条没被拦住"）

```
现象：<某个坏数据竟然通过了校验>
期望：<应该报 X 规则错误>
实际：<通过了 / 报的是 Y 规则>

请：
1. 先给出复现该行数据的最小 Excel（3 行以内）
2. 打印这一行在解析层长什么样（值 + 类型）
3. 判断是"规则没配"、"规则配了但没执行"还是"执行了但判断写反了"
4. 验证后再改
```

**"没配 / 没执行 / 判断写反"这三分类**能让你在 5 分钟内定位，而不是漫无目的地读 500 行。

### 5.3 评分与门禁验证（你这一岗的核心验收）

```
请帮我构造一个反例，证明"高分不能蒙过门禁"：
- 一份 100 行的数据，其中 1 行必填字段为空（致命），其余 99 行完全合规
- 期望：总分 > 85（甚至 > 90），但 passed = false，fatal_count = 1
给出：造数据的代码 + 断言 + 实际运行输出。

如果实际 passed = true，说明门禁逻辑有 bug，先修 bug 再谈别的。
```

**这条用例是"你这一岗"存在的证明**，必须有一条，且必须真的跑出 `passed=false`。

### 5.4 配置化回归验证

```
请验证"改 YAML 就能改行为"这个卖点：
1. 读当前 config/rules.yaml 的 pass_threshold
2. 用同一份数据跑两次：threshold 正常值 / threshold=10
3. 输出两次的 total_score、threshold、passed 对照表
4. 给出对应的 pytest 用例代码
```

如果改阈值行为没变，说明阈值被写死在代码里了——这是"配置外置"这条铁律的检测手段。

## 六、你这个角色专属的技巧

### 1. 让 AI 先写"规则的语义定义"，再写实现

八类规则听起来简单，但边界很脏。先让它说清：

```
请为这八类规则各写一句"精确语义"，必须回答边界：
- required：空字符串算空吗？全角空格算吗？0 算空吗？
- type：整数 "12" 和 "12.0" 都算 number 吗？
- range：边界值含不含？空值跳过还是报错？
- unique：大小写敏感吗？软删的记录算不算？
- foreign_key：目标记录被软删了算存在吗？
- regex：全匹配还是部分匹配？
- length：算字符数还是字节数？去不去空格？
- enum：大小写敏感吗？允不允许同义词？

先只给语义，不要代码。
```

这张表出来之后，写代码是机械劳动；表没出来就写代码，必然反复改。

### 2. 唯一性校验必须问"作用域"

```
unique 规则的比较范围是什么？
1. 仅本批数据内
2. 仅数据库已有数据
3. 本批 + 数据库

三种选择分别会导致什么误判？项目应该选哪种？为什么？
```

正确答案通常是第 3 种（本批内重复 + 库里已存在都要拦），但代价是要查库。让它把代价说清楚，你再决定。

### 3. 报告导出用 openpyxl，别用 CSV

G05-32 要 Excel 报告。CSV 在中文 Windows 上默认 GBK，双击打开就是乱码。

```
导出 Excel 报告（不是 CSV），要求：
1. 明细页：行号 / 列 / 规则 / 说明 / 原值
2. 汇总页：各 sheet 得分、通过率、致命错误数
3. 中文不乱码（openpyxl 原生支持，不要用 CSV 绕）
4. 同时给一个 JSON 版本，字段与接口返回一致
```

### 4. 让 AI 检查"规则执行是只读的"

```
检查 validator.py：规则执行过程中有没有修改原始数据？
列出所有对入参 rows 的写操作（包括 rows[i][k] = ...）。
如果有，说明为什么不该有：校验器改数据会让 C1 入库的内容和业务方看到的原始文件不一致。
```

## 七、红线（对 AI 说什么都不行）

| 不许 | 为什么 |
|---|---|
| `passed = total_score >= threshold` | 本项目踩过的坑，87 分放行脏数据 |
| 把阈值/权重/枚举写进 Python | 违反"配置外置"，丢掉核心卖点 |
| 校验器修改原始数据 | 只读，否则入库内容和原始文件不一致 |
| `foreign_key` 只查同批数据 | 库里明明有也会误判 |
| 用 `enumerate` 下标当行号 | 业务方按行号找不到人 |
| 改 `bulk_importer.py` | 归 C1 |
| 改 `models/*` | 归 B1 |
| 报告里加未和 C1/C4 对齐的字段 | 他们会跟着错 |
| 用 CSV 导出中文报告 | Excel 打开乱码 |

## 八、常见翻车与应对

| 现象 | 原因 | 应对 |
|---|---|---|
| 87 分的数据进库了 | 评分盖过了致命错误 | 加 `fatal_count == 0` 条件 |
| 改 YAML 没效果 | 值被写死在代码里 | 全局搜阈值数字，改成从 settings 读 |
| 外键明明存在却报错 | 只查了同批数据，或没过滤软删 | 查库 + `is_deleted.is_(False)` |
| 行号差 2 | enumerate 下标 | 用 Excel 真实行号 |
| 唯一性误判 | 比较范围选错 | 明确"本批 + 库"两种都要查 |
| 空字符串没被 required 拦住 | `if not value` 对 `" "` 失效 | 统一 `strip()` 后判断，含全角空格 |
| 评分算出 100 但明显有错 | 合规性分母算错（把没校验的也算进去了） | 分母只算"被校验过的单元格" |
| C1 说 report 字段对不上 | 你改了字段名 | 字段是契约，改名前先说 |

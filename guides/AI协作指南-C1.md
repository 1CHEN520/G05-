# AI 协作指南 · C1（周翔）

> 读者：你自己。**《任务指导书-C1》是给 AI 读的，这份是给你读的。**
> 你的活有一个"要么全进、要么全不进"的死规矩：**整批原子回滚。**
> 所以你的 AI 用法核心是：**先让它把事务边界画出来，再让它写代码。**

## 一、用哪种 AI

| 优先级 | 工具形态 | 具体建议 | 为什么适合你 |
|---|---|---|---|
| **主力** | 能读文件 + 能跑命令的 Agent 型（Cursor Agent / Claude Code） | 任选 | 你要反复造 10000 行 Excel 测耗时，必须让它自己跑、自己看数字 |
| **主力补充** | 同一个 Agent，指定"openpyxl，不许用 pandas" | 每次重申 | AI 默认会给你 `pd.read_excel()`，那是 40MB 依赖 + 额外的类型推断坑 |
| **备选** | 网页对话（DeepSeek / Kimi） | 查 openpyxl 的 API、看报错 | 但它看不到你的 `bulk_importer.py`，给的代码常常和你已有的 `report` 结构不匹配 |
| **不推荐** | 纯 Tab 补全 | — | 补全出来的 `for row in ws.iter_rows()` 十有八九把表头当数据 |

**一条硬要求**：每次让它写解析代码，开头加一句"**只用 openpyxl，禁止 pandas；行号必须是 Excel 真实行号**"。

### 它应该怎么回答（判断有没有读懂）

| 检查点 | 合格回答 |
|---|---|
| 事务边界 | 说得出"整个导入一个 session，最后一次 commit"，不是每行 commit |

## 五、日常四类提示词

### 5.1 写导入逻辑

```
请实现 <具体步骤>，按顺序输出：
1. 事务边界：从哪开始、到哪结束、异常在哪捕获、回滚在哪执行
2. 内存策略：一次性读全表还是流式？分批大小多少？为什么
3. 代码（类型注解 + 中文注释）
4. 三条 pytest：全部合法 / 一行非法（整批 0 行）/ 空文件

先给 1、2，我确认后再写代码。
```

**"事务边界"必须写在最前面**。先写代码再补事务，十个有九个会漏回滚。

### 5.2 排错（解析类）

```
我用 openpyxl 读 <文件>，结果不对：
期望：<比如"5 行数据">
实际：<比如"6 行，多了一行空行">

请：
1. 先给我一段 5 行以内的代码，把每行的原始值打印出来（含行号、类型）
2. 根据输出判断问题在"读取"还是"过滤"
3. 再给修复
```

**先打印原始值**。AI 猜"可能是合并单元格"，但你打印出来可能发现是末尾多了个 `None` 行。

### 5.3 性能优化（G05-27 必须交的东西）

```
10000 行导入现在 <X> 秒，目标是 <30 秒。请按这个顺序帮我定位：
1. 给出分段计时的代码（解析 / 校验 / 写入 三段各多少秒）
2. 根据分段结果判断瓶颈在哪
3. 针对瓶颈给 3 个优化方案，每个说明"预期提升多少 + 有什么代价"
4. 优化后必须重跑三次，取中位数，并给出优化前后对比表
```

**必须分段计时**。不分段就优化，等于闭眼改代码——很可能你优化的是只占 5% 的那一段。

### 5.4 提交前自检


## 六、你这个角色专属的技巧

### 1. 让 AI 先解释"分批 flush 不等于分批提交"

这是最容易写错的地方，也是"整批回滚"能不能成立的关键：

```
请用一段话解释：如果我在循环里每 1000 行 session.flush() 一次，
最后校验失败时 session.rollback()，前面 1000 行会不会进库？为什么？
```

正确答案：**不会**。flush 只是把 SQL 发给数据库（在事务内），rollback 会把整个事务撤销。如果它答"会进库"，说明它把 flush 当 commit 了，它写的代码不能信。

### 2. 让 AI 生成"坏 Excel 生成器"，而不是手工造数据

测试需要各种脏数据。别手工改 Excel：

```
写一个 pytest 夹具，用 openpyxl 生成 5 个坏文件，每个只坏一处：
1. 编号格式错（小写）
2. 必填列为空
3. 枚举值不在允许范围
4. 编号重复
5. 外键指向不存在的设备
每个文件 3 行数据，其余正常。返回文件路径列表。
```

这样每次跑测试都是全新生成，不依赖仓库里的二进制文件。

### 3. 上传接口要有大小限制（AI 不会主动加）

```
检查 /api/import 的上传接口：
- 有没有文件大小上限？
- 有没有文件类型校验（只收 .xlsx）？
- 有没有 sheet 名不匹配时的友好报错？
- 超大文件会不会把内存打满？
给出缺口清单和修复方案。
```

### 4. 让 AI 帮你和 C2 对齐契约

```
我调用 C2 的 RuleEngine，返回的 report 我要用到这些字段：<列出>。
请检查 src/g05/importers/validator.py 里 report 的实际结构，逐个字段核对：
字段名 / 类型 / 是否一定存在 / 我是否用对了。
有对不上的，明确写"字段 X 我以为是 A，实际是 B"。
```

**这是你和 C2 之间唯一的接口**，对不上就是集成时炸。

## 七、红线（对 AI 说什么都不行）

| 不许 | 为什么 |
|---|---|
| 引入 pandas | 依赖膨胀 40MB，且类型推断会悄悄改变数据 |
| 每行 commit | 10000 行 = 10000 次 fsync，必然超时；且无法整批回滚 |
| 校验失败后"跳过坏行继续导入" | 违反"整批原子"这条验收标准 |
| 用 `enumerate` 下标当行号 | 报错位置差 1~2 行，业务方找不到人 |
| 改 `validator.py` | 归 C2。你只调用，不改 |
| 改 `models/*` | 归 B1 |
| 让上传接口无大小限制 | 一个 200MB 文件能把服务打挂 |
| 接受"性能应该没问题" | 必须三次实测取中位数 |

## 八、常见翻车与应对

| 现象 | 原因 | 应对 |
|---|---|---|
| 导入 10000 行要 3 分钟 | 每行 commit | 改成单事务 + 分批 flush |
| 校验失败但库里有数据 | 中途 commit 过 | 检查有没有 `commit()` 写在循环里 |
| 行号对不上 | 用了 enumerate | 用 `ws.iter_rows(min_row=2)` 配合真实行号 |
| 数字变字符串 | Excel 单元格类型是文本 | 解析层统一 `strip()` + 尝试转数值，转不了保留原文 |
| 空行被当数据 | 没过滤全空行 | `all(v is None or str(v).strip() == "" for v in row)` |
| 中文列名读不到 | 表头有空格/全角字符 | 表头也 `strip()` + 去全角空格 `\u3000` |
| 内存爆掉 | 一次性把所有行读进 list | 用生成器逐行 yield |
| 导入成功但列表页看不到 | 没 commit，或设备被软删了 | 检查 commit 与 `is_deleted` |

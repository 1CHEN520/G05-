# AI 协作指南 · C4（唐国莉）

> 读者：你自己。**《任务指导书-C4》是给 AI 读的，这份是给你读的。**
> 你是全组工时最重的（33h），也是**唯一"老师肉眼可见"**的一环。
> 所以你的 AI 用法核心是：**先让它把"三态"和"错误码"写进模板，再写功能。**

---

## 一、用哪种 AI

| 优先级 | 工具形态 | 具体建议 | 为什么适合你 |
|---|---|---|---|
| **主力** | 能读文件 + 能跑命令的 Agent 型（Cursor Agent / Claude Code） | 任选 | 你要一边改后端一边刷页面，必须让它自己 `curl` 验证 |
| **主力补充** | 同一个 Agent，前端单独开一个会话 | 前后端别混在一个上下文里 | 混在一起时它会把 FastAPI 的写法带进 JS，或者把 JS 的 `async` 带进 Python |
| **备选** | 网页对话 | 查 FastAPI 参数校验、CSS 布局 | 免费好用，但拿不到你的 `dto.py`，字段名容易编 |
| **不推荐** | 前端生成器（v0 / 各类"AI 生成页面"） | — | 它们默认引入 Tailwind/React/CDN，直接违反"零依赖离线可用" |

**一条硬要求**：每次让它写前端，开头加一句"**原生 HTML/CSS/JS，禁止任何 CDN、框架、构建工具**"。不加，它会很自然地给你 `import React`。

## 五、日常四类提示词

### 5.1 写接口

```
请实现 <接口>，按顺序输出：
1. 契约：入参（含校验规则）/ 出参 / 可能的错误码
2. 业务前置校验：有哪些"不满足就拒绝"的条件？分别返回什么状态码？
3. 事务与审计：在哪写、写什么 action、reason 怎么写
4. 代码
5. 两条 pytest：正常路径 + 一个错误路径

先给 1、2、3，我确认后再写代码。
```

**第 2 步是关键**：AI 默认只写"happy path"，错误路径要你逼它想。

### 5.2 写页面

```
请实现 <页面>，硬约束：
- 原生 HTML/CSS/JS，禁止 CDN / 框架 / 构建工具
- 必须有 loading / 空态 / 错误态 三种呈现
- 所有用户数据渲染前经过 esc()
- 分页、搜索要能在 URL hash 里体现（可分享、可刷新）

按顺序给：
1. HTML 骨架（含三态容器）
2. JS 渲染函数（含三态切换）
3. 样式（复用 app.css 里已有的 CSS 变量，不要新增硬编码颜色）
先给 1，我确认后再给 2、3。
```

### 5.3 排错（前后端联调类）

```
现象：<比如"页面一直显示加载中">
DevTools 里看到：<贴 Network 状态码 / Console 报错 / 响应体>

请：
1. 先判断问题在"请求没发出"、"请求发出但 404/500"、"响应到了但渲染失败"三段中的哪一段
2. 给一条最小验证命令（curl 或 Console 一行）
3. 验证后再改
```

**分三段判断**能省一半时间。AI 最爱直接猜"可能是 CORS"，但你 curl 一下就知道根本不是。

### 5.4 提交前自检

## 六、你这个角色专属的技巧

### 1. 让 AI 先"造数据"，再写页面

页面空着看不出问题。先让它生成演示数据：

```
给我一段脚本，往库里造 3 类演示数据：
1. 正常设备 20 台，覆盖 5 种设备类型
2. 有 1 台设备的名称包含特殊字符 <>&"'（用来验证 esc 生效）
3. 有 1 台设备下挂 30 个测点（用来验证分页）
不要写进 scripts/ 目录（那里不归我），直接在命令行执行。
```

第 2 类数据是**你验证 XSS 防护的唯一手段**，必须造。

### 2. 分页 bug 用"边界四问"定位

```
针对 /api/devices 分页，请逐条验证并给输出：
1. page=1&size=5，total 是多少？items 几条？
2. 最后一页（total 不是 size 整数倍）items 几条？
3. page 超出总页数，items 是空列表还是报错？
4. 带 keyword 过滤后，total 是过滤后的数还是全表数？
```

第 4 条是最常见的 bug：`total` 忘了带过滤条件。

### 3. 让 AI 生成"错误码对照表"，再让它实现

```
先给我一张错误码表：场景 / HTTP 状态码 / code / message 模板。
覆盖：编号重复、外键不存在、参数格式错、资源不存在、有活跃子资源不能删、未预期异常。
我确认后，你再按这张表实现。
```

表定了，实现就不会前后不一致（同一类错误有时 400 有时 409 是评审必挑的毛病）。

### 4. 断网测试要提前做，别到答辩才试

```bat
:: 1. 起服务，浏览器打开页面
:: 2. DevTools → Network → 勾 Offline
:: 3. 刷新
```

预期：**页面结构完整渲染**，只是数据请求失败并显示错误态。
如果整页空白 → 你有资源是外链，或 JS 在顶层抛异常没兜住。

### 5. 改名接口的"影响面"要能被前端读懂

```
rename 接口返回的 affected 结构是什么？请给一个真实示例 JSON，
并说明前端要展示哪几个数字（受影响节点数 / 按类型分布 / 是否有环）。
如果 affected 是空的（该测点没有任何下游），前端应该显示什么？
```

**空影响面**是个容易被忽略的边界：显示"0 个受影响"比什么都不显示更让人放心。

## 七、红线（对 AI 说什么都不行）

| 不许 | 为什么 |
|---|---|
| 引入 CDN / React / Vue / Tailwind / 构建工具 | 断网即白屏，验收直接不过 |
| 改 `schemas/dto.py` | 契约归 A，改了会让 C1/C2/B2 跟着错 |
| 物理删除（`session.delete`） | 全项目软删 |
| 500 响应返回 `str(exc)` | 泄露内部结构，安全项扣分 |
| `_g05_skip_audit` 设在没有显式审计的路径上 | 等于关掉审计 |
| 只写成功态，不写 loading / 空 / 错误态 | 演示必翻车 |
| `innerHTML` 拼接不过 `esc()` | XSS |
| 改 `main.py` 的路由注册 / lifespan | 那是全组入口，只加异常处理器 |
| 用 `PUT` 覆盖全字段做局部更新 | 用 `PATCH` + `exclude_unset`，否则没传的字段会被清空 |

## 八、常见翻车与应对

| 现象 | 原因 | 应对 |
|---|---|---|
| 最后一页是空的 | `total` 没带过滤条件 | 共用 `conditions` 列表 |
| 更新接口把没传的字段清空了 | 用了 PUT + 全量 model_dump | 改 PATCH + `exclude_unset=True` |
| 审计里操作人全是 anonymous | 前端没带 `X-Operator` | `api()` 里统一注入请求头 |
| 改名后列表还是旧名字 | 前端没重新拉数据 | 改名成功后重新加载当前页 |
| 页面断网就白屏 | 有外链资源 | 搜 `http` 关键字清干净 |
| 中文设备名显示成 `&amp;` | 双重转义 | `esc()` 只用一次，别在模板里再转 |
| 删除设备报 500 | 外键约束 | 先查活跃测点返回 409 |
| 500 页面显示一堆 Python 堆栈 | 没配全局异常处理器 | 加 handler，返回 `trace_id` |
| 页面能开但样式全乱 | `app.css` 路径错 | 静态挂载在 `/static`，引用要写 `/static/css/app.css` |

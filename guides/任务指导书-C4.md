## 五、技术要点

### 1. 分页的 `total` 和 `items` 必须用**同一组** where 条件

最常见的 bug：`count` 忘了加 `is_deleted` 过滤，导致 `total=100` 但只能翻到 80 条，最后一页是空的。

```python
conditions = []
if not include_deleted:
    conditions.append(Device.is_deleted.is_(False))
if keyword:
    like = f"%{keyword}%"
    conditions.append(Device.device_name.like(like) | Device.device_code.like(like))

for cond in conditions:          # 同一个 conditions 同时喂给两条语句
    stmt = stmt.where(cond)
    count_stmt = count_stmt.where(cond)
```

**别复制粘贴条件**——复制出来的两份迟早不一致。

### 2. 越界页返回空列表，不报错

```python
# 前端翻到第 999 页是正常操作，不是错误
stmt = stmt.limit(size).offset((page - 1) * size)   # offset 超出总数 → 空列表
```

`page` / `size` 的边界用 `Query(1, ge=1)` / `Query(20, ge=1, le=200)` 在入口拦住，**不要**自己写 `if page < 1: raise`。

### 3. 软删三步，一个都不能少

```python
device.is_deleted = True
device.deleted_at = datetime.now(timezone.utc)
device.version += 1              # ← 忘了这个，版本链就断了
```

软删前还要做**业务前置校验**：设备下还有活跃测点时拒绝删除（返回 409），否则会产生孤儿测点。

```python
active_points = db.execute(
    select(func.count()).select_from(MeasurePoint)
    .where(MeasurePoint.device_id == device_id, MeasurePoint.is_deleted.is_(False))
).scalar_one()
if active_points:
    raise HTTPException(409, f"设备下仍有 {active_points} 个活跃测点，请先处理测点")
```

### 4. 改名不删行：影响面要在**改名之前**算

```python
# ✅ 先算影响面（此时 point_code 还是旧的，语义上是"改名前评估"）
result = impact_of(session, node_type="point", node_key=point.point_code, direction="downstream")

# 再更新三个字段
point.renamed_from = old_name
point.point_name = new_name
point.version += 1
point.change_note = reason
```

**为什么顺序重要**：`point_code` 在改名中不变，所以理论上前算后算结果一样；但语义上"改名会影响谁"必须基于改名前的状态回答，而且一旦以后支持改 `point_code`，后算就是错的。

### 5. 写操作必须能追溯到人

`X-Operator` 缺失时默认 `anonymous`，但这只用于容错，**前端每个写请求都要带上**：

```javascript
async function api(path, opts = {}) {
  opts.headers = Object.assign({ "X-Operator": currentOperator() }, opts.headers || {});
  ...
}
```

审计表里一屏 `anonymous` 的记录，等于没有审计。操作人建议存 `localStorage`，页头放一个输入框让人填名字。

### 6. 与 C3 的约定：显式审计要打标记

你写业务审计（带 `reason`），C3 的自动埋点会重复记一条。约定是：

```python
device._g05_skip_audit = True    # 我下面自己记，你别插手
db.flush()
AuditService.record(db, table_name="device", action="UPDATE", operator=operator, ..., reason="更新设备信息")
db.commit()
```

**这个标记只在"你显式调 `AuditService.record`"时才设**。纯自动埋点的路径（比如直接 `db.add`）不要设，否则就没审计了。

### 7. 前端零依赖是硬约束，不是偏好

- **不许** `<script src="https://cdn.jsdelivr.net/...">`。教室断网、答辩现场断网，页面就白了。
- **不许**引入 Vue/React/ECharts。图表用原生 SVG 画（B2 的 `lineage.js` 就是这么做的）。
- 不用构建工具。改完 `app.css` / `*.js` 刷新浏览器就生效。

### 8. `esc()` 是 XSS 的唯一防线

所有用户数据进 `innerHTML` 之前必须过一遍：

```javascript
function esc(s) {
  return String(s ?? "").replace(/[&<>"']/g, (c) =>
    ({ "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;", "'": "&#39;" }[c]));
}
// 用法：`<td>${esc(d.device_name)}</td>`
```

设备名里出现 `<img onerror=...>` 这种输入是完全可能的（导入来自外部 Excel），漏一处就是漏洞。

### 9. 每页三态，缺一不可

| 态 | 触发 | 呈现 |
|---|---|---|
| loading | 请求发出未返回 | 骨架屏或"加载中…"，**不要**留空白 |
| 空态 | 返回 0 条 | "还没有数据，先去导入页上传一份" + 跳转按钮 |
| 错误态 | `api()` 抛异常 | 红色提示 + 重试按钮 + 错误信息 |

只写"成功态"的页面，演示时网络一抖就是一片空白，老师会以为系统崩了。

### 10. 错误码分段 + trace_id

| 段 | 含义 | HTTP | 例子 |
|---|---|---|---|
| `G05-1xxx` | 参数错误 | 400/422 | 设备编号格式不合法 |
| `G05-2xxx` | 业务冲突 | 404/409 | 编号已存在、设备下有活跃测点 |
| `G05-5xxx` | 系统错误 | 500 | 数据库不可用 |

500 的响应体**绝不能**带堆栈：

```python
return JSONResponse(status_code=500, content={
    "ok": False,
    "code": "G05-5001",
    "message": "服务内部错误，请查看服务端日志",
    "trace_id": trace_id,          # 用户报障时报这个号，你拿它去日志里捞堆栈
})
```

日志里 `log.exception(...)` 要带上同一个 `trace_id`，否则这个号没用。

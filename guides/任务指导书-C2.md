## 五、技术要点（这一节是全项目最容易做错的地方）

### 1. 评分 ≠ 门禁（踩过坑，务必保留）

曾经的错误实现：

```python
report.passed = report.total_score >= report.threshold   # ❌ 87 分就放行
```

后果：一份数据必填字段缺了 3 个，但因为其他字段都合规，总分 87 > 阈值 85，**脏数据进库了**。

正确实现：

```python
FATAL_RULES = frozenset({"required", "unique", "foreign_key"})
report.fatal_count = sum(1 for i in report.issues if i.rule in FATAL_RULES)
report.passed = (report.total_score >= report.threshold) and (report.fatal_count == 0)
```

**为什么这三类是致命的**：缺必填 → 下游拿不到关键信息；主键重复 → 数据会被覆盖或报错；外键悬空 → 产生孤儿记录。这三类不是"质量差一点"，是"结构不成立"。

**普通问题**（`enum` / `range` / `regex` / `length`）可以靠高分容忍，因为它们不破坏引用完整性。

### 2. 三档评分怎么算

```
完整性 completeness = 非空单元格数 / 应有单元格数 × 100
合规性 compliance   = 通过类型/枚举/范围/regex 校验的单元格 / 校验过的单元格 × 100
唯一性 uniqueness   = (1 - 重复值数 / 总行数) × 100

total = completeness×0.40 + compliance×0.35 + uniqueness×0.25
```

权重和阈值都在 `config/rules.yaml` 的 `scoring` 段，**不许写死在代码里**。

### 3. 外键规则必须查库

```python
# ✅ 查库：设备编号在 device 表里存在吗
exists = session.execute(
    select(Device.id).where(Device.device_code == value, Device.is_deleted == False)
).first()
```

**不要**只在本批数据里找——本批 10000 行都不含某设备，但库里明明有，会误判。

### 4. 问题定位到 Excel 真实行号

`row` 是 Excel 里的行号（表头是第 1 行），不是 `enumerate` 的下标。差 2 行，业务方就找不到人。

### 5. 报告结构要和 C1、C4 对齐

`report.to_dict()` 里这几个字段是**被别处依赖的契约**：

```python
{
  "sheet": "device", "total_rows": 100, "valid_rows": 98, "invalid_rows": 2,
  "issue_count": 3, "bad_rows": [...], "scores": {...},
  "total_score": 87.2, "threshold": 85.0, "passed": false,
  "fatal_count": 1, "issues": [{row, column, rule, message}]
}
```

要加字段可以，要改名先跟 C1、C4、A 说。

### 6. 规则可配置的回归测试

`tests/test_validator.py` 里必须有一条：**改 YAML 阈值 → 行为随之变化**。

```python
rules = copy.deepcopy(settings.rules)
rules["scoring"]["pass_threshold"] = 10
engine = RuleEngine(rules=rules)
report = engine.validate("device", rows)
assert report.threshold == 10
```

这条用例是"配置驱动"这个卖点的**唯一证据**，别删。

# G05 需求规格说明书

> 阶段 1 产出物 · SLA 检查点：用户故事 ≥8 + 非功能需求带数字

## 一、项目边界

### 1.1 做什么

把 12 类设备的台账从 Excel 迁入结构化资产目录，实现：

- 设备 / 测点 / 记录 / 告警 四类资产的统一建模
- 测点改名时能算出"影响哪些报表和任务"（血缘）
- 任何变更留下不可篡改的审计痕迹
- Excel 批量导入带质量门禁

### 1.2 不做什么（明确排除）

| 排除项 | 理由 | 归属项目 |
|---|---|---|
| 实时数据采集 | 属采集中枢职责 | G01 / G07 |
| 数据质量清洗管道 | 只做导入门禁，不做持续清洗 | G02 |
| KPI 可视化大屏 | 只提供资产目录查询 | G04 |
| 用户登录与权限 | 用 `X-Operator` 头模拟操作人 | G10 |
| 千万行时序优化 | 记录表只做基础索引 | G08 |

### 1.3 干系人

| 角色 | 关注点 | 验收权重 |
|---|---|---|
| 资产管理员 | 导入效率、错误定位 | 高 |
| 工艺工程师 | 改名影响面是否清晰 | 高 |
| 审计人员 | 变更能否追溯到人 | 高 |
| 运维人员 | 重启能否自愈、日志能否定位 | 中 |
| 课程评委 | 硬指标实测、故障注入表现 | 高 |

## 二、用户故事（12 条）

### US-01 批量导入设备台账

> **作为**资产管理员，**我要**上传 Excel 一次性导入设备与测点，**以便**不用逐条录入。

**验收条件**
- 支持 `.xlsx/.xlsm`，单次 ≤200000 行
- 校验不通过时**一条都不写入**，返回打回单
- 打回单每条问题标注 **Excel 实际行号**（含表头计数）
- 万行导入 <30s

### US-02 查看设备-测点层级

> **作为**资产管理员，**我要**看到某台设备下挂了哪些测点，**以便**盘点资产完整性。

**验收条件**：`GET /api/devices/{id}/points` 返回测点清单，含类型与单位

### US-03 测点改名并预知影响面

> **作为**工艺工程师，**我要**在改测点名之前知道会影响哪些报表，**以便**提前通知相关方。

**验收条件**
- 改名接口返回受影响节点清单，含类型、名称、负责人、**完整依赖路径**
- 影响面查询 <1s
- 旧名保留在 `renamed_from` 字段

### US-04 追溯任意一条变更

> **作为**审计人员，**我要**按时间/操作人/对象查到变更前后内容，**以便**定位责任。

**验收条件**
- 审计记录含 old/new 完整快照
- 支持按表名、业务键、操作人、动作、时间区间组合筛选
- 导出 CSV 中文不乱码（带 BOM）

### US-05 审计不可被篡改

> **作为**审计人员，**我要**确保没人能偷偷改审计记录。

**验收条件**：直接对 `audit_log` 发 `UPDATE`/`DELETE` 被数据库拒绝，错误信息含 `append-only`

### US-06 调整校验规则不改代码

> **作为**资产管理员，**我要**调整必填项或阈值，**以便**适配新设备类型。

**验收条件**：只改 `config/rules.yaml`，重启后生效，代码零改动

### US-07 定位坏行

> **作为**资产管理员，**我要**打回单直接告诉我第几行第几列出错。

**验收条件**：打回单表格含「Excel行号 / 列 / 规则 / 说明 / 当前值」

### US-08 防止孤儿数据

> **作为**系统管理员，**我要**保证测点一定属于真实存在的设备。

**验收条件**：插入不存在 `device_id` 的测点，数据库抛 `FOREIGN KEY constraint failed`

### US-09 软删除保留痕迹

> **作为**资产管理员，**我要**"删除"测点后仍能查到历史。

**验收条件**：删除后行仍在库中，`is_deleted=1`，`version` 递增，审计留 `SOFT_DELETE` 记录

### US-10 一键启动

> **作为**新接手同学，**我要**三条命令跑起整个系统。

**验收条件**：`init_db → seed_data → main`，无额外手工步骤，无需外网

### US-11 查看血缘全图

> **作为**数据分析师，**我要**看到测点到报表的整体依赖网络。

**验收条件**：`GET /api/lineage/graph` 返回节点+边，前端力导向渲染，节点按类型着色

### US-12 强杀后自愈

> **作为**运维人员，**我要**进程被 `kill -9` 后重启数据不丢。

**验收条件**：强杀后 `PRAGMA integrity_check = ok`，已提交数据全部可读

## 四、数据需求

### 4.1 数据规模假设

| 实体 | 首年预估 | 设计容量 |
|---|---|---|
| 设备 Device | 60~200 | 10 万 |
| 测点 MeasurePoint | 200~800 | 50 万 |
| 记录 Record | 千万级 | 单表 + 归档 |
| 告警 Alarm | 万级/年 | 百万 |
| 审计 AuditLog | 十万级/年 | 千万（append-only） |

### 4.2 数据质量要求

| 维度 | 要求 | 落地 |
|---|---|---|
| 完整性 | 必填列非空率 100% | 校验规则 `required` |
| 合规性 | 编号符合编码规范 | 正则 `^[A-Z]{2,4}-\d{3,6}$` |
| 唯一性 | 业务键不重复 | 校验 `unique` + 数据库唯一约束 |
| 参照完整性 | 测点必须挂在存在的设备下 | 外键 + `PRAGMA foreign_keys=ON` |
| 可追溯 | 每次变更留痕 | 审计表 + 触发器 |

### 4.3 数据保留

| 数据 | 在线保留 | 归档 | 说明 |
|---|---|---|---|
| 设备/测点 | 永久（软删） | — | 资产目录不可丢 |
| 记录 | 90 天 | 冷备文件 | `config/database.yaml` |
| 告警 | 1 年 | — | |
| 审计 | **永久** | — | 合规要求，禁止删除 |

## 五、约束与假设

### 5.1 技术约束

- 数据库限定 SQLite（课程环境，无独立 DB 服务）
- 不引入消息队列、缓存中间件等外部依赖
- 前端零 CDN（离线可演示）

### 5.2 业务假设

- 设备编号在集团内唯一（`device_code`）
- 测点编号全局唯一（`point_code`），改名不改编号
- 一个测点只属于一台设备
- 报表/任务通过 `point_code` 引用测点（血缘依据）

### 5.3 已知限制

| 限制 | 影响 | 后续方案 |
|---|---|---|
| SQLite 单写者 | 高并发写会串行 | 迁 PostgreSQL（接口层已抽象） |
| 血缘需手工注册边 | 新报表接入要写代码 | 提供 SDK 自动埋点（G17 方向） |
| 无认证 | 操作人靠请求头 | 对接 G10 统一登录 |
| 无定时任务 | 周报需手工触发 | 接入调度框架 |

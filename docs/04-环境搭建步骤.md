# G05 环境搭建步骤（pp03 · Windows x64 · Python 3.12）

> 版本：2026-10-26 ｜ 基于本机实测（`D:\Anacoda\Anac\envs\pp03`）
> 适用：G05 全体组员在自己的机器上搭一套等价环境
> 对照物：`environment.yml`（第 1 层）、`requirements.txt` / `requirements-dev.txt`（第 2、3 层）、`pyproject.toml`（第 4 层）

---

## 一、总览：四层结构

pp03 不是"一个 conda 环境装一堆包"，而是**四层叠加**。理解这一点就不会装错：

| 层 | 装什么 | 谁来装 | 数量 |
|---|---|---|---|
| **第 1 层** Conda 基础 | Python 3.12.15 + pip | `conda env create -f environment.yml` | 18 个 |
| **第 2 层** 运行依赖 | SQLAlchemy / FastAPI / uvicorn / pydantic / PyYAML / openpyxl / python-multipart | `pip install -r requirements.txt` | 7 直接 + 传递共 26 个 |
| **第 3 层** 开发工具 | pytest / pytest-cov / httpx / ruff | `pip install -r requirements-dev.txt` | 4 直接 |
| **第 4 层** 项目本体 | g05-asset-catalog | `pip install -e .` | 1 个（editable） |

**关键原则：第 1 层只用 conda，第 2/3/4 层全部用 pip。** 不要用 conda 装 sqlalchemy/pydantic，否则会和 pip 装的版本打架，而且 `pip check` 查不出来。

## 三、完整搭建步骤

### 步骤 0：前置检查

打开 **Anaconda Prompt**（不要用普通 PowerShell，原因见坑 1）：

```powershell
conda --version      # 需 >= 23.x，本机实测 26.9.3
conda env list       # 确认没有已存在的 pp03
```

已有 pp03 时**不要删除覆盖**，先 `conda activate pp03` 看 `python --version` 是不是 3.12.x。

### 步骤 1：创建 Conda 环境

在仓库根目录（有 `environment.yml` 的那层）：

```powershell
conda env create -f environment.yml
```

验证：

```powershell
conda activate pp03
python --version                          # 必须 3.12.x
python -c "import sys; print(sys.executable)"   # 路径必须含 envs\pp03
```

### 步骤 2：安装运行依赖

```powershell
python -m pip install -r requirements.txt
```

> 本仓库的 requirements 是**锁定版本**的，可以直接 `-r`。如果看到 TODO 或没写版本号的 requirements，不要裸装，逐条指定版本（见坑 6）。

### 步骤 3：安装开发工具

```powershell
python -m pip install -r requirements-dev.txt
```

### 步骤 4：安装项目本体

在仓库根目录执行（注意末尾的点和两个 `--no-`）：

```powershell
python -m pip install --no-deps --no-build-isolation -e .
```

- `-e`：editable，改代码立即生效
- `--no-deps`：依赖已在第 2/3 层装好，不让 pip 再动一遍
- `--no-build-isolation`：用当前环境的 setuptools 构建，避免临时拉一套构建依赖

### 步骤 5：验收（五条全过才算装好）

```powershell
# (1) 依赖一致性
python -m pip check
# 期望：No broken requirements found.

# (2) 关键包导入
python -c "import sqlalchemy, fastapi, uvicorn, pydantic, yaml, openpyxl, multipart; print('imports OK')"

# (3) 确认 g05 指向本仓库（最容易出错的一条）
python -c "import g05; print(g05.__file__)"
# 期望：<你自己的仓库>\src\g05\__init__.py

# (4) 环境自检（输出 JSON，passed 必须为 true）
python -m g05 preflight
# 期望：{"project": "g05-asset-catalog", "passed": true, ...}

# (5) 测试
python -m pytest -q
# 期望：46 passed
```

## 四、一键安装脚本

仓库根目录已有 `setup_pp03.ps1`，在**已激活 pp03** 的 Anaconda Prompt 里执行：

```powershell
cd D:\G05
powershell -ExecutionPolicy Bypass -File .\setup_pp03.ps1
```

脚本做五件事：前置检查 → 装依赖 → editable 安装 → `pip check` → 确认 `g05` 指向本仓库 → 跑 preflight 与 pytest。任何一步失败都会红字报错并退出，不会带着坏环境往下走。

> 脚本**不会**替你 `conda activate`，因为第 1 层归 conda 管。

## 六、七个必踩的坑（按踩中概率排序）

### 坑 1：在普通 PowerShell 里 `conda activate` 静默失败

**现象**：`conda activate pp03` 不报错，但 `python --version` 是别的版本，`import g05` 报 `ModuleNotFoundError`。

**原因**：`conda init powershell` 没执行过，PATH 上别的 Python 抢在 conda 前面。

**解决**（三选一）：
1. 用 **Anaconda Prompt**（最省事）
2. `conda init powershell` 后**重开终端**
3. 不激活，直接用 `conda run`：
   ```powershell
   conda run --no-capture-output -n pp03 python -m pytest -q
   ```

**自查**：`python -c "import sys; print(sys.executable)"` 路径必须含 `envs\pp03`。

---

### 坑 2：`conda env create` 报 `Could not find 'share/conda-launchers/cli-64.exe'`（本机实测踩中）

**现象**：依赖解算成功、包也下载完，卡在 `Preparing transaction: ...failed`，堆栈末尾是

```
FileNotFoundError: Could not find 'share/conda-launchers/cli-64.exe' in the
conda-launchers package. Install conda-launchers with support for 'win-64'.
```

但 `D:\Anacoda\Anac\share\conda-launchers\cli-64.exe` 明明存在。

**原因**：base 环境里 `conda-meta\conda-launchers-*.json` 这条包记录被写坏了——`paths_data.paths` 是空数组。conda 创建新环境时要按记录里的路径去找启动器模板（用来生成 `pip.exe` / `uvicorn.exe` 这些），记录里没有路径就找不到，于是报"包缺文件"。

**验证方法**：

```powershell
python -c "import json; d=json.load(open(r'D:\Anacoda\Anac\conda-meta\conda-launchers-24.7.1-hd3eb1b0_6.json',encoding='utf-8')); print(len(d['paths_data']['paths']))"
# 正常应输出 4；输出 0 就是踩中了
```

**解决**：用包缓存里的 `info\paths.json` 把记录补回去（先备份原文件）：

```powershell
python -c "
import json, shutil, pathlib
meta = pathlib.Path(r'D:\Anacoda\Anac\conda-meta\conda-launchers-24.7.1-hd3eb1b0_6.json')
pkg  = pathlib.Path(r'D:\Anacoda\Anac\pkgs\conda-launchers-24.7.1-hd3eb1b0_6\info\paths.json')
shutil.copy2(meta, meta.with_suffix('.json.bak'))
rec = json.loads(meta.read_text(encoding='utf-8'))
rec['paths_data'] = {'paths_version': 1, 'paths': json.loads(pkg.read_text(encoding='utf-8'))['paths']}
meta.write_text(json.dumps(rec, ensure_ascii=False, indent=2), encoding='utf-8')
print('repaired')
"
```

改完重跑 `conda env create -f environment.yml` 即可。**不要**为此去 `conda install -n base conda-launchers --force-reinstall`，那是更大的动作。

### 坑 3：g05 的 editable 指向了别人的目录

**现象**：在自己仓库里跑 pytest 结果莫名其妙；`import g05` 输出的不是自己的路径。

**原因**：editable 安装会在 `site-packages` 写 `.pth` 记录**绝对路径**。谁在别的目录执行过 `pip install -e .`，指针就指向那里。

**解决**：

```powershell
python -m pip uninstall -y g05-asset-catalog
cd <本组仓库根目录>
python -m pip install --no-deps --no-build-isolation -e .
python -c "import g05; print(g05.__file__)"   # 必须是自己目录
```

**每次换目录工作前都自查这一条**，它不会报错，只会让你测错代码。

---

### 坑 4：`conda` 一启动就刷三行 entry point 报错

**现象**：

```
Error while loading conda entry point: conda-anaconda-telemetry
  (cannot import name 'CondaRequestHeader' from 'conda.plugins')
Error while loading conda entry point: conda-anaconda-tos
Error while loading conda entry point: repo
```

**原因**：base 里装的 conda 插件版本落后于 conda 本体（插件调用了新版本删掉的 API）。

**影响**：**只是噪音，不影响功能**。`conda env list` / `create` / `install` 都能正常用。

**应对**：
- 嫌烦可以 `CONDA_NO_PLUGINS=true conda ...`，但注意它同时会禁用 libmamba 求解器，需要补 `--solver classic`
- 真要修：`conda install -n base -c defaults --force-reinstall conda-anaconda-telemetry conda-anaconda-tos`
- **不要**为了消这三行去重装 Anaconda

---

### 坑 5：`.pytest_cache` 目录权限损坏

**现象**：

```
PytestCacheWarning: could not create cache path ...\.pytest_cache\v\cache
[WinError 5] 拒绝访问
```

**原因**：该目录被别的账号（例如沙箱账号）创建过，Owner 不是当前用户。

**应对**：

```powershell
python -m pytest -q -p no:cacheprovider      # 临时绕过
takeown /f .pytest_cache /r /d y              # 彻底修复（需管理员）
icacls .pytest_cache /reset /t
```

同类问题也会让 git 报 `detected dubious ownership`，临时绕过：`git -c safe.directory=<仓库绝对路径> status`。

---

### 坑 6：裸装 requirements 装出错误版本

**现象**：装完 `pip check` 通过，但运行时报 API 不存在。

**原因**：`requirements.txt` 若没锁版本，`SQLAlchemy` 可能装到 2.1（去掉了某些 2.0 写法），`fastapi` 可能装到 0.116+（行为变化）。

**应对**：本仓库的 requirements **已锁死版本**，直接 `-r` 没问题；如果哪天被人改成不锁版本，回到 `git log` 找锁定版，或按本文第二节的表格逐条装。

---

### 坑 7：Windows 上数据库文件被占用

**现象**：跑测试或 `init_db.py --drop` 时报 `PermissionError: [WinError 32] ... g05.db`。

**原因**：另开着一个 `python -m g05 serve` 进程占着 SQLite 文件。Windows 不允许删除被打开的文件（Linux 允许）。

**应对**：

```powershell
# 先停掉服务（Ctrl+C），或找出占用进程
netstat -ano | findstr :8000
taskkill /PID <pid> /F
```

**这也解释了为什么测试用临时库**：`tests/conftest.py` 每个用例建独立临时文件，不碰 `data/db/g05.db`，所以测试和开发服务可以同时跑。

| 重建数据库 | `python -m g05 initdb --drop` |

## 八、本文的边界

1. **只覆盖 Windows x64 + Python 3.12**。macOS / Ubuntu 需要另做验证，不能照抄（尤其坑 2、坑 7 是 Windows 特有）。
2. **只保证环境能装、能导入、能跑测试**。不代表性能达标或验收通过——那是 `scripts/fault_inject.py` 与 `scripts/bench.py` 的事。
3. **版本号来自本机 2026-10-26 的实测快照**。上游发新版本后本文不会自动更新。
4. **没有覆盖 `conda init` 的副作用**：它会给 PowerShell 加钩子，不想要就改用 Anaconda Prompt 或 `conda run`。

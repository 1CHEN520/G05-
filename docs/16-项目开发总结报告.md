## 二、开发过程回顾（四里程碑）

1. **M1 契约冻结**：DTO 与 24 个错误码先行评审冻结，四个角色实现一次对齐，评审零返工——「契约先行」是本项目最大方法论收获；
2. **M2 内核层**：B1 七表 ORM + B2 血缘引擎按期合入；归属清单纪律建立（先查归属再改文件）；
3. **M3 功能层**：四个功能角色全部交付本人 PR；规则引擎经历一次重做（列名别名/行级报错/一票否决）；
4. **M4 联调结项**：联调抓出 4 个真实缺陷（seed argv / bench 基准 / 审计-业务分离 / preflight 假绿）全部修复并配守护测试。

## 三、关键经验（做对的）

1. **契约先冻结**：接口契约是全组并行开发的地基；
2. **每合一个 PR 当场实测**：评审不能只读描述（B1 的 PR 描述写绿实测是红）；
3. **纪律文档化**：AGENTS.md 固化归属/验收/红线，进度失控靠它扭转；
4. **证据链可复现**：对账/EXPLAIN/故障注入/基线 JSON 全部脚本化，答辩现场可跑；
5. **诚实声明边界**：跨浏览器仅一轮抽测、hover 仅部分节点——如实标注比含糊宣称更专业。

## 四、关键教训（做错的）

1. **自检工具自己有 bug**：preflight 只建表不装触发器，全组看到的绿是旧库假绿（#65 修复）——自检工具也需要被测试；
2. **发包 ≠ 开工**：任务书发了 5 人迟迟不推代码——纪律文档化 + 逐个盯才清零；
3. **性能数字带病上场**：bench 查不存在的节点得 0.18ms（#77 重构为真实 200 节点图）——数字必须核对数据构造；
4. **PR 编号硬编码事故**：误查已合并 PR 的 CI 状态造成假合并（#86 补救）——编号必须动态获取、合并后必须验证 state=MERGED。

## 五、遗留问题与改进方向

| 遗留 | 说明 | 改进方向 |
|---|---|---|
| 认证模块缺失 | 设计取舍（本阶段无用户体系） | L3：PBKDF2 哈希 + operator 从请求身份取 |
| 单机存储上限 | SQLite 单写者（已 WAL + busy_timeout 缓解，320 并发实测无锁） | L3：PostgreSQL + 连接池 |
| 跨浏览器仅一轮抽测 | 时间边界 | L3：自动化兼容测试矩阵 |
| 高级采集接入 | OPC-UA/MQTT 仅有变更单+双人复核流程定义 | L3：旁路采集落地 |

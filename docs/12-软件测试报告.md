## 二、src 与 test 一一对应关系表

每个被测模块都有对应测试文件（评测可现场核对：`pytest --collect-only -q` 按文件名对齐）：

| 被测模块（src/g05） | 测试文件（tests/） | 覆盖重点 |
|---|---|---|
| models/（7 表） | test_models.py | 字段约束、软删版本链、外键级联 |
| core/schema.py | test_schema.py | 建表、触发器装载自检 |
| api/routes/*（审计域） | test_api.py / test_audit.py / test_audit_auto.py | CRUD、审计快照、行级埋点 |
| api/routes/*（C4 CRUD） | test_c4_api.py | 设备/测点 CRUD、错误码、改名联动 |
| importers/bulk_importer.py | test_importer.py | 万行导入、原子回滚、打回单 |
| importers/validator.py | test_validator.py | 六类规则、别名、YAML 行级报错 |
| lineage/impact.py | test_lineage.py + test_lineage_validation.py | BFS、环检测、诚实截断、200 节点性能断言 |
| reports/export.py | test_report_export.py | Excel/JSON 双格式导出与内容一致性 |
| schemas/errors.py | test_error_contract.py | 24 码语义、1xxx→4xx / 5xxx→5xx |

**映射结论**：17 个测试文件 ↔ 13 个被测模块组，src 与 test 一一对应，无未覆盖源文件（覆盖率 87%，schemas/errors.py 与 models/audit_log.py 100%）。

## 三、单元测试

- **269 个用例全部通过**（`pytest -q`，13s）；总覆盖 **87%**（schemas/errors.py、dto.py、audit_log.py、lineage 100%）。
- 测试用例按 GB/T 15532 思路组织：每条用例有前置条件（隔离临时库）、操作步骤、预期断言与实际输出；守护测试纪律为「**每个修复必须验证测试真的能抓到**」（如防篡改用例在空表上测不出效果的缺陷即由此纪律发现）。
- 用例分布：数据层 99 条（C5）→ 血缘 32+ 条（B2）→ 审计加固 514 行（C3）→ 导入/校验/契约/API 各域（C1/C2/C4/A）合计 269。

## 四、集成测试

- **TestClient 全链路**：`GET/POST/PUT` 实际经路由→service→DB（含触发器与自动审计）验证返回与库内状态一致。
- 端点级集成：22+ 端点全部 200 实测；改名 → 版本链 → 血缘 → 审计四表联动验证（US-03：new_version=2、affected.total=11）。
- 前后端集成：控制台四页实测渲染 + XSS 转义 + 断网错误态（C4 浏览器实测，证据见 PR #62）。

## 五、性能测试（bench.py，20 次采样取中位数与 p95）

| 指标 | 中位数 | p95 | 目标 | 结论 |
|---|---|---|---|---|
| 批量导入（20 设备×3 测点） | 20.49ms | 28.07ms | 5000ms | ✅ |
| 血缘影响面（**三层 200 节点全量下游**） | 4.53ms | 11.68ms | 200ms | ✅ |
| 列表分页（200 设备/1000 测点） | 3.94ms | 4.39ms | 100ms | ✅ |
| 审计查询（200 条 limit=200） | 1.56ms | 1.86ms | 200ms | ✅ |

补充实测：**万行 Excel 导入 1.14s**（阈值 <30s）；机器可读结果 `reports/bench-baseline.json`；方法学与历史修正见 `reports/性能基线报告.md`（旧 0.18ms 系查询不存在节点，已废弃）。

## 六、压力测试（fault_inject.py --all，5/5 PASS）

| 用例 | 注入方式 | 预期 | 实测 |
|---|---|---|---|
| orphan | 插入孤儿测点 | 外键拒绝 | ✅ 零写入 |
| tamper | UPDATE/DELETE audit_log | 触发器 ABORT | ✅ 全拦截 |
| dirty | 坏行 Excel | 整批打回 | ✅ 行号定位、零残留 |
| kill | 强杀 -9 模拟断电 | WAL 自愈 | ✅ integrity_check=ok，落盘可读 |
| concurrent | 8 线程 × 40 条 | 无锁、计数一致 | ✅ 320/320 入库 0.37s |

**压力后对账**：`python scripts/reconcile.py` 五组恒等（外键/软删/行级审计可定位/血缘无孤儿/批次声明守恒）全部成立——即「崩溃且能恢复」的直接证据。

## 七、缺陷与处置记录

| 缺陷 | 级别 | 处置 |
|---|---|---|
| preflight 建表不装触发器（假绿） | 高 | 修复 + 回归测试（#44） |
| 审计快照时机错位 | 中 | C3 #57 修正 + 防篡改加固 |
| seed 子命令 argv 透传报错 | 中 | 隔离 argv + 守护测试（#68） |

| bench 符号迁移未同步 | 中 | 一行 import 修复（#73，C5 专属工作区提交） |

全部缺陷均闭环（修复 + 回归验证 + 守护测试证明拦截有效）。

## 八、测试结论

1. 269 个单元用例、四级测试全部通过，src 与 test 一一对应，覆盖率 87%。
2. 性能与压力指标全部优于阈值，且数字来自可复现脚本与 JSON 证据。
3. 故障注入与对账恒等构成「崩溃且能恢复」的完整证据链，可支撑教师现场任意注入验证。

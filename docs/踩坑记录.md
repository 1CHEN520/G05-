## 1. SQLite 外键默认是关的

**现象**
插入 `device_id=999999` 的测点，竟然成功了。孤儿记录进库，直到报表 join 不出数据才发现。

**根因**
SQLite 出于向后兼容，`PRAGMA foreign_keys` 默认是 **OFF**。`ForeignKey(...)` 在 ORM 层只是"声明"，不执行 `PRAGMA` 就没有任何约束力。

**解法**
在 Engine 的 `connect` 事件上注入 PRAGMA，保证**每个新连接**都开启：

```python
event.listen(engine, "connect", _apply_pragmas)
# 里面执行 PRAGMA foreign_keys=ON
```

**预防**
- `/healthz` 把 `foreign_keys` 作为自检项，未开启直接报 `ok: false`
- 单测 `test_foreign_keys_pragma_on` 断言值为 1
- 单测 `test_orphan_point_rejected` 断言插入抛 `IntegrityError`

## 2. 自动审计和显式审计重复记录

**现象**
改一次测点名，审计表出现**两条**：一条 `UPDATE`（自动埋点），一条 `RENAME`（显式写入）。前端时间线看起来像改了两次。

**根因**
`before_flush` 事件对所有 `session.dirty` 对象无条件写审计，而 `rename_point()` 里又显式调了 `AuditService.record()`。

**解法**
给对象加 `_g05_skip_audit` 标记，自动埋点看到就跳过并清除标记：

```python
point._g05_skip_audit = True   # 服务层：我自己会写
# before_flush 里：
if getattr(obj, "_g05_skip_audit", False):
    obj._g05_skip_audit = False
    continue
```

**预防**
原则：**有业务语义的变更（改名/软删）由服务层显式写，带 reason；其余交给自动埋点。**
测试 `test_rename_via_service_writes_audit` 断言只产生 1 条 `RENAME`。

## 3. 质量评分把结构性错误"算过去"了

**现象**
必填列空着，但总分 90 分（完整性 75% × 40 + 合规性 100% × 35 + 唯一性 100% × 25 = 90），高于阈值 85，**放行了**。

**根因**
评分模型是加权平均，单项扣分被其他满分项摊薄。1 行数据缺 1 个必填，完整性只掉到 75%，加权后仍能过线。

**解法**
引入 `FATAL_RULES` 概念，结构性错误一票否决：

```python
FATAL_RULES = {"required", "unique", "foreign_key"}
passed = total_score >= threshold AND fatal_count == 0
```

**预防**
- 单测 `test_fatal_rule_cannot_be_offset_by_score`：阈值降到 1 分，必填缺失依然打回
- 打回单明确标注 `打回(结构性错误)` 而非笼统的 `打回`

**反思**
加权评分适合衡量"数据质量趋势"，不适合做"能否入库"的判定。两者要分开：**评分看趋势，门禁看硬条件。**

## 4. 触发器只在生产有，测试环境没有

**现象**
单测里"审计表不可改"的断言失败了 —— 但手工跑 `fault_inject.py` 明明是好的。

**根因**
触发器 DDL 一开始写在 `scripts/init_db.py` 里，测试夹具自己建表时**没有**执行这些 DDL。结果测试环境的审计表可以随便改。

**解法**
把 DDL 抽到 `src/g05/core/schema.py`，由三处共同引用：

```
init_db.py        ─┐
main.py (启动)    ─┼──► core/schema.apply_triggers()
tests/conftest.py ─┘
```

**预防**
原则：**约束定义必须单点维护。** 任何"只在某个入口才生效"的约束，都是定时炸弹。

## 5. 血缘查询返回了对象但拿不到总数

**现象**
`result.total` 报 `AttributeError`。

**根因**
`ImpactResult` 是个 dataclass，只有 `nodes` 字段。`to_dict()` 里算了 `"total": len(self.nodes)`，但没给对象本身加属性。前端和测试都习惯用 `.total`。

**解法**
加 `@property total`：

```python
@property
def total(self) -> int:
    return len(self.nodes)
```

**预防**
对外暴露的数据结构，**dict 视图和对象视图要一致**。测试优先用对象属性断言，能暴露这类不一致。

## 6. 中文测点编码过不了正则

**现象**
样例数据导入得分 93，180 条 `regex` 报错：`point_code 格式不合法: FAN0001_振动`。

**根因**
`rules.yaml` 里 `point_code` 的正则是 `^[A-Z0-9_]{2,48}$`，只允许 ASCII。而 `seed_data.py` 生成时直接用了中文类型名拼接。

**解法**
加中英映射表，测点编码用英文缩写：

```python
POINT_CODE = {"振动": "VIB", "温度": "TEMP", "压力": "PRESS", ...}
# FAN0001_振动 → FAN0001_VIB
```

**预防**
**样例数据必须过自己的校验规则。** 现在 `seed_data.py` 生成的 Excel 会先被 `RuleEngine` 校验，不过就报警。

顺带发现：这条正则本身是对的 —— 工业编码规范就该是 ASCII，中文放在 `point_name` 里。**是造数据的人错了，不是规则错了。**

## 7. `kill -9` 后文件被占用，删不掉数据库

**现象**
想重置数据库，`rm data/db/g05.db` 报"操作被中止"，WAL 和 SHM 文件也删不掉。

**根因**
服务进程还在跑，SQLite 持有文件句柄。Windows 下被占用的文件无法删除（Linux 可以 unlink，但进程仍持有）。

**解法**
用 `init_db.py --drop` 走 SQL 层 `DROP TABLE`，不需要删文件：

```bash
python scripts/init_db.py --drop    # 先 DROP 再 CREATE
python scripts/seed_data.py --reset # 清业务表（审计表保留，因为禁删）
```

**预防**
运维手册 §5 写明：重置数据用 `--drop`/`--reset`，不要手工 `rm` 数据库文件。

## 8. 子进程脚本的花括号被 format 吃掉

**现象**
`fault_inject.py --case kill` 报 `KeyError: 'i'`。

**根因**
用 `_WRITER.format(src=...)` 注入路径，但脚本内容里有 f-string 的 `{i:04d}`，`.format()` 把它当成占位符解析了。

**解法**
改用显式占位符 + `replace`，不碰花括号：

```python
_WRITER = r'''... sys.path.insert(0, r"__SRC__") ... "KILL-%04d" % i ...'''
script = _WRITER.replace("__SRC__", src)
```

**预防**
**凡是"代码里嵌代码"的场景，不要用 `format`/`f-string` 拼模板。** 用 `replace` + 独特占位符，或 `string.Template`。

## 9. `cascade="all, delete-orphan"` 让外键 RESTRICT 失效

**现象**
想验证"有测点的设备不能物理删除"，但删设备时测点被一起删了，`IntegrityError` 没抛出来。

**根因**
`Device.points` 配了 `cascade="all, delete-orphan"`，SQLAlchemy 在 `session.delete(device)` 时会**先删子对象**，再删父对象。数据库的 `ondelete="RESTRICT"` 根本没机会生效。

**解法**
去掉 `delete-orphan`，只保留 `passive_deletes=True`，让数据库约束说话：

```python
points = relationship(back_populates="device", passive_deletes=True, lazy="selectin")
```

**预防**
**ORM 的 cascade 和数据库的 ondelete 是两套机制，会互相遮蔽。** 想让数据库约束生效，就必须关掉 ORM 层的主动级联。

业务上我们本来就要"有测点的设备不许删"，所以这个改动同时修正了语义。

## 10. 日志 JSON 里塞不进自定义字段

**现象**
`log.info("import.done", extra={"file": "a.xlsx"})` 报 `KeyError: "Attempt to overwrite 'file' in LogRecord"`。

**根因**
`file` 是 `LogRecord` 的保留属性名（还有 `msg`、`args`、`levelname`、`module`、`lineno` 等）。`extra` 不能覆盖这些键。

**解法**
统一用一个不冲突的容器键：

```python
log.info("import.done", extra={"extra_fields": {"file": "a.xlsx", "rows": 1000}})
```

再自定义 Formatter 把 `extra_fields` 平铺进 JSON 行：

```json
{"ts":"...","level":"INFO","logger":"g05.importers","msg":"import.done","data":{"file":"a.xlsx","rows":1000}}
```

**预防**
封装 `log_event(logger, event, **fields)` 统一入口，业务代码不直接碰 `extra`。

# G05 用户手册（设备部用户版）

> 对应国标 GB/T 8567-2006《用户手册》。面向**设备部日常用户**（非开发人员）——教你把系统用起来；《运维巡检清单》（docs/06）与《运行手册》（docs/runbook.md）面向运维人员。维护者：C6（王新宇）。

## 一、系统能帮你做什么

| 场景 | 以前（Excel） | 现在（本系统） |
|---|---|---|
| 改一个测点编号 | 翻全表核对下游报表/任务，漏一个就是事故 | 影响面自动列出全部下游对象（实测 200 节点 4.5ms） |
| 查「谁改的、改了什么」 | 无据可查 | 审计自动记录谁/何时/前后快照/原因，且不可篡改 |
| 月度数据上报 | 手工整理 240 行 | 4 个统计查询一键导出 csv |
| 新员工熟悉设备 | 翻 Excel + 问老师傅 | 台账四页看板一屏掌握 |

## 二、开始使用（三条命令）

```bash
conda activate pp03
python -m g05 preflight        # 环境自检（8/8 通过即可用）
python -m g05 serve            # 启动服务，浏览器打开 http://127.0.0.1:8000
```

首次使用先灌演示数据：`python -m g05 initdb --drop && python -m g05 seed`（60 台设备 / 180 个测点）。

## 三、四页控制台

### 1. 设备台账页
- 看：设备列表（编号/名称/型号/车间/状态/版本）、KPI 看板（60 台 / 180 测点）
- 做：按设备编号搜索；查看设备详情（含版本链 is_deleted/version/superseded_by）

### 2. 测点管理页
- 看：测点列表及其所属设备
- 做：新增测点（选设备）、测点改名（**改名会自动触发血缘预警**：提示新版本号 v2 + 影响下游 N 个对象）

### 3. 血缘影响面页
- 用法：输入测点编号（如 FAN0001_VIB）→ 查看下游全部受影响对象
- 读结果：`total`（全部下游数）/ `returned`（本次返回数）/ `truncated_by`（被截断原因）——**被截断也会如实告诉你**；`cycles` 为空即无环路

### 4. 审计页
- 看：全部变更记录（谁/何时/哪张表哪一行/改前改后快照/原因）
- 查：按操作人、时间、业务键过滤；CSV 导出
- 证据：`POST /api/audit/verify-immutable` 可现场验证审计不可篡改（UPDATE/DELETE 均被数据库拒绝）

## 四、批量导入（月度上报场景）

```bash
python -m g05 import data/sample/sample_devices.xlsx   # 万行实测 1.14 秒
```

- 支持 Excel/JSON 双格式打回单：**坏行带行号**返回，整批原子回滚（不会半批入库）；
- 校验规则六类（缺失/格式/范围/唯一/外键/业务），关键规则**一票否决**；
- 模板见 `docs/05-导入模板说明.md`。

## 五、常见问题

| 问题 | 解法 |
|---|---|
| 页面打不开 | 先跑 `python -m g05 preflight` 看 passed 是否 true；再确认 8000 端口未被占用 |
| 导入报「UNIQUE constraint」 | 数据已在库里——用 `python -m g05 initdb --drop && python -m g05 seed` 重置演示库 |
| 报错带 G05-xxxx 代码 | 按 `docs/02` 第七节错误码表查含义；错误体里的 trace_id 可给运维定位日志 |
| 数据「不见了」 | 本系统删除是软删——查审计页定位操作记录，数据在版本链里可追溯 |
| 想导出统计报表 | 见《软件测试报告》第四节 4 个统计查询；或将控制台对应页导出 |

# G05 软件质量保证计划

> 对应国标 GB/T 8567-2006《软件质量保证计划》。质量保证过程（GB/T 8566 支持过程）的成册定义：谁负责、用什么方法、按什么标准、留什么证据。维护者：A（陈锦妍）· C5（测试执行）。

## 一、质量目标（量化）

| 维度 | 目标 | 实测 |
|---|---|---|
| 单元测试 | 全绿，用例数 ≥15 | **269 个全绿**（17.9 倍） |
| 覆盖率 | ≥80% | **87%**（schemas/errors/dto/audit_log/lineage 100%） |
| 代码规范 | pylint ≥8.5 | **9.00/10**（CI 门禁 --fail-under=9.0） |
| 性能 | 四类阈值全达标 | 全达标（导入 26 倍 / 血缘 41 倍余量） |
| 可靠性 | 故障注入全过 + 对账恒等 | **5/5 + 5/5** |
| 需求追溯 | 全部可追溯 | 28 条需求全部映射到 issue（矩阵） |

## 四、质量活动与工具链

1. **静态检查**：pylint（≥9.0 硬门禁）+ black（格式）+ Ruff（CI 第一道）；
2. **守护测试纪律**：每个缺陷修复必带守护测试，且验证「能抓到」（空表上测防篡改无效）；
3. **自检工具自测**：preflight 自身的行为也要有测试覆盖（教训：只建表不装触发器的假绿，#65 fail-fast）；
4. **故障注入**：5 类（孤儿/篡改/脏数据/强杀/并发）——从「怕出事」到「敢被注入」；
5. **对账恒等**：5 组恒等脚本化，故障后依然成立 = 「崩溃且能恢复」的直接证据；
6. **证据链**：数字必须标注「测什么/没测什么/由谁决定」；基线以仓库 JSON 为准（±10% 波动正常）。

## 五、不符合项处理

发现即记录（issue）→ 复现 → 修复附守护测试 → 回归全绿 → 关闭。重大不符合项（假绿/数字失真/契约违约）升级至组长终审并写入踩坑记录（docs/踩坑记录.md，8 条：问题→根因→解法→预防）。

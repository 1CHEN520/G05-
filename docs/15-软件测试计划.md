# G05 软件测试计划

> 对应国标 GB/T 8567-2006《测试计划》（测试「计划」与「报告」分离：本文档定义测什么/怎么测/通过标准；《软件测试报告》（docs/12）记录实测结果）。维护者：C5（韩永健）· A（计划评审）。

## 一、测试范围与对象

| 对象 | 说明 |
|---|---|
| 被测系统 | 工业设备台账与测点资产目录（FastAPI + SQLAlchemy + SQLite/WAL） |
| 测试分层 | 单元测试（pytest）→ 集成测试（REST 端到端）→ 性能测试（bench.py）→ 压力测试（fault_inject.py） |
| 不在本轮范围 | 认证模块（设计取舍，见 docs/01 边界界定）；浏览器兼容全量覆盖（仅一轮抽测） |

## 二、测试策略与用例分布

| 层级 | 工具 | 用例规模 | 覆盖重点 |
|---|---|---|---|
| 单元测试 | pytest + SQLite 内存库 | 269 个（阈值 ≥15） | 数据层 99 / 血缘 32+ / 审计加固 514 行测试 / 导入 / 校验 / 契约 / API |
| 集成测试 | httpx/TestClient | 端到端断言 | 22+ 端点全链路：读取→清洗→入库→查询→审计 |
| 性能测试 | scripts/bench.py | 20 次采样取中位数+p95 | 四类指标（见第四节阈值表） |
| 压力测试 | scripts/fault_inject.py | 5 类注入 | 孤儿/篡改/脏数据/强杀/并发 |
| 对账验证 | scripts/reconcile.py | 5 组恒等 | 外键/软删/行级审计/血缘/批次守恒 |

## 三、测试通过标准（验收红线）

1. `pytest tests/ -q` 全绿（0 failed）；
2. 覆盖率 ≥ 87%（关键模块 schemas/errors/dto/audit_log/lineage 100%）；
3. EXPLAIN QUERY PLAN：核心 SQL 无纯表扫描（SCAN 无 USING 视为未命中）；
4. 故障注入 5/5 PASS，且注入后 `reconcile.py` 五组恒等依然成立；
5. pylint ≥ 9.0（CI 门禁 --fail-under=9.0）。

## 四、性能阈值表（bench.py 判定依据）

| 指标 | 目标 | 达标实测（基线 JSON 为准） |
|---|---|---|
| 批量导入（万行） | < 30s | 1.14s（26 倍余量） |
| 血缘影响面（200 节点） | < 1s | 4.50ms / p95 12.13ms |
| 列表分页 | < 100ms | 4.12ms / p95 5.05ms |
| 审计查询 | < 200ms | 1.56ms / p95 1.86ms |

## 五、故障注入用例清单

| 用例 | 注入方式 | 预期行为 |
|---|---|---|
| ① 孤儿记录 | 测点挂不存在设备 | 外键拒绝，零写入 |
| ② 审计篡改 | UPDATE/DELETE audit_log | 触发器 ABORT（绕过应用层也拒绝） |
| ③ 脏数据行 | 坏行混入导入 | 行号打回 + 整批原子回滚零残留 |
| ④ 强杀进程 | kill -9 写入中途 | WAL 自愈，integrity_check=ok，对账 5/5 |
| ⑤ 并发写 | 8 线程 × 40 条 | 320/320 入库无 database is locked |

## 六、测试纪律（守护测试）

1. 每个缺陷修复必须附带守护测试，并验证「能抓到」（空表上测防篡改 = 无效测试）；
2. 测试库每次独立建库，杜绝脏状态污染基线；
3. 性能基准先审数据构造（教训：0.18ms 查空节点的假成绩，#77 重构为真实 200 节点图）；
4. src 与 test 一一对应（对应表见《软件测试报告》docs/12 第二节）。

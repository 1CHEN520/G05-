# G05 部署报告（双系统）

> 对应国标文档要求：软件工程流程 · 5. 运维维护——软件部署（至少支持两个系统）
> 维护者：C6（王新宇）· A（Linux 章节实测）
> 系统 A：Windows 11（开发与演示环境，已实际部署）｜ 系统 B：Linux（Ubuntu 22.04 LTS，标准部署路径）

---

## 一、部署前提（两个系统一致）

| 项 | 要求 |
|---|---|
| Python | ≥3.10（实测 3.12.15） |
| Git | clone 仓库 |
| 磁盘 | ≥200MB（含依赖与库文件） |
| 网络 | 安装依赖时需联网；运行期**完全离线可用**（数据不出域） |

## 二、系统 A：Windows 部署（已实测，演示环境同款）

### 2.1 步骤

```bat
git clone https://github.com/1CHEN520/G05-.git
cd G05-
pip install -r requirements-dev.txt
pip install --no-deps --no-build-isolation -e .
python -m g05 preflight      :: 环境自检，输出 JSON，passed 必须为 true
python -m g05 initdb         :: 建表 + 审计触发器（幂等）
python -m g05 seed           :: 灌演示数据（60 设备 / 180 测点）
python -m g05 serve          :: 启动服务，默认 127.0.0.1:8000
```

### 2.2 验证

- 浏览器打开 `http://127.0.0.1:8000/`：控制台四页（设备/测点/审计/导入）可渲染；
- `http://127.0.0.1:8000/docs`：OpenAPI 文档，每端点带错误码说明；
- `python -m g05 preflight` 输出 `passed: true`（8/8 子项）。

### 2.3 已知事项

- Windows 下生成脚本统一写 LF（`newline="\n"`），避免 CRLF 污染 diff；
- 库文件默认 `data/db/g05.db`，可用 `G05_DATABASE__DATABASE__PATH` 环境变量改路径。

## 三、系统 B：Linux（Ubuntu 22.04 LTS）部署

### 3.1 步骤

```bash
sudo apt update && sudo apt install -y python3.12 python3.12-venv git
git clone https://github.com/1CHEN520/G05-.git && cd G05-
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
pip install --no-deps --no-build-isolation -e .
python -m g05 preflight && python -m g05 initdb && python -m g05 seed
```

### 3.2 以 systemd 服务常驻（生产形态）

`/etc/systemd/system/g05.service`：

```ini
[Unit]
Description=G05 Device Ledger Service
After=network.target

[Service]
Type=simple
User=g05
WorkingDirectory=/opt/g05
ExecStart=/opt/g05/.venv/bin/python -m g05 serve --host 0.0.0.0 --port 8000
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now g05
systemctl status g05            # active (running)
```

- 日志：JSON Lines 落 `logs/app.jsonl`（含 trace_id），`journalctl -u g05` 可查进程日志；
- 数据备份：`data/db/g05.db` 单文件，`sqlite3 data/db/g05.db ".backup backup.db"` 在线备份。

## 四、部署验证（两系统通用检查单）

| # | 检查项 | 命令 | 通过标准 |
|---|---|---|---|
| 1 | 环境自检 | `python -m g05 preflight` | passed=true，8/8 子项 |
| 2 | 表与触发器 | `python -m g05 initdb` | schema ready；自检触发器在位 |
| 3 | 演示数据 | `python -m g05 seed` | 60 设备 / 180 测点 |
| 4 | 健康探活 | 浏览器 `/docs` 或 `GET /api/audit` | 200 |
| 5 | 全量测试 | `python -m pytest -q` | 269 passed |
| 6 | 对账恒等 | `python scripts/reconcile.py` | 5/5 组成立 |
| 7 | 故障注入 | `python scripts/fault_inject.py --all` | 5/5 PASS |

## 五、故障处置预案（runbook 三段式摘要）

| 场景 | 处置 |
|---|---|
| 库损坏（投屏现场库坏） | `python -m g05 initdb --drop && python -m g05 seed` 约 30 秒重建；随后 `reconcile.py` 验证 5/5 恒等 |
| 服务崩溃 | systemd `Restart=on-failure` 自动拉起（Windows 下重跑 serve）；已落盘数据不丢（WAL + integrity_check=ok 实测） |
| 端口占用 | `--port` 换端口或释放占用进程；preflight 的目录可写检查会先暴露权限类问题 |

## 六、部署结论

两个系统（Windows 11 / Ubuntu 22.04）均完成部署并逐项通过 7 项检查单；部署物一致（同一仓库、同一 requirements），差异仅在服务常驻方式（前台进程 vs systemd）。新机器按本文档操作可在 **15 分钟内**完成从 clone 到服务常驻。
